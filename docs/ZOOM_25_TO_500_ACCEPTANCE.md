# 25%—500% 原生缩放验收

## 实测边界

网页不能可靠禁止浏览器原生缩放，也不能让所有字号在25%—500%保持相同物理尺寸。本版以宽视口视觉舞台、正常倍率既有构图、高倍率可阅读重排为目标；没有CSS zoom、整页反向scale、DPR伪造或Ctrl快捷键拦截。

自动化采用**有真实窗口的 Chromium 扩展 tabs.setZoom/getZoom**，每次读取同一tabId/windowId和窗口bounds，不用setViewportSize冒充。完整截图来自原生渲染、保留原始尺寸；OS显示缩放使100% DPR可能不等于1，DPR仅诊断。浏览器版本：156.0.8078.4。

**MANUAL VERIFICATION REQUIRED / PENDING MANUAL**：没有自动点击浏览器菜单缩放控件。下面API原生倍率测试通过不等同于全部浏览器菜单、Edge、跨显示器或实机手机已人工通过。各档33/67用1/3与2/3 API精确值，菜单通常显示约33%/67%；实际值以JSON为准。

## 恢复与降级

- Projects进入实际横向Pin后执行100→25→100→500→100，保存项目slug和原Pin进度；每次回100%恢复原滚动位置，反向wheel有效。高倍率Pin退出后纵向阅读，重新回宽视口恢复。
- About Pin在100/125/100检查读取位置。Craft键帽在25/100/200/500检查真实按下，500%使用2.5D。媒体弹出、前进/后退、关闭后来源焦点和项目图片比例均测试。
- Craft、Resume门禁、Community有15档数据；游戏三个详情测25/100/500。认证Resume/PDF另测100/200/500，敏感截图仅本机private/resume/qa/v12-native，不公开打包。
- 1440×900、1920×1080与390×844、430×932属于独立响应式测试，不能当作原生倍率证据。

## 由本人执行的浏览器菜单验收

1. 打开FULL_NODE本地或自己的HTTPS站点，固定一个物理窗口。浏览器菜单→缩放，确认100%，截图必须包含菜单显示倍率。
2. 按25、33、50、67、75、90、100、125、150、175、200、250、300、400、500逐档调整；不提供的档位标记“不支持”，不要用CSS替代。记录浏览器版本、系统显示缩放、屏幕和窗口尺寸。
3. 各档检查Hero人物/签名、About、Projects、Craft、公开页面、三服与详情；500%滚动到按钮后能够聚焦、点击，不能只看首屏就判断丢失。
4. Projects中途进行100→25→100→500→100，反向滚动、打开截图、浏览器后退；Craft开图后缩放再关闭，键帽按压正确命中。
5. 正式Resume在私有测试中登录，检查PDF、打印、登出后拒绝。截图不得公开包含私人内容。
6. 记录每档 PASS/FAIL/不支持与截图路径；有问题保留错误，修复后复测，不用“构建成功”代替。
